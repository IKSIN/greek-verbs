# Импорт слов из Telegram — дизайн

Дата: 2026-10-14

## Цель

В Telegram-группе «Greek» Анна с марта 2025 записывает слова с уроков. Нужно:

1. Один раз перенести в общий словарь всё накопленное: около 1000 строк-кандидатов, после чистки ожидается 600–800 записей.
2. Дальше автоматически добавлять новые слова из группы без участия человека.

Добавляется всё: слова любых частей речи и фразы. Часть речи становится полем словаря,
по нему можно фильтровать.

## Критерии успеха

- После разового импорта в `data/words.json` есть очищенные слова из чата:
  - без домашних заданий, переписки и дублей;
  - опечатки исправлены, глаголы в словарной форме;
  - у каждой записи есть `pos`.
- Слово, написанное в группе, появляется в словаре не позже чем через ~2 часа, а бот отвечает в группу, что добавил.
- Ошибка OpenRouter или Telegram не теряет сообщения и не ломает словарь.
- Неверно распознанное слово можно исправить или удалить в приложении, как любое пользовательское.

## Вне рамок

- Фото и аудио из чата не распознаются (OCR, распознавание речи).
- Отдельного экрана «Входящие» с подтверждением нет: бот коммитит сразу.
- Синхронизация в обратную сторону (из приложения в Telegram) не делается.

## Изменения модели данных

### Поле `pos`

```ts
type Pos = 'verb' | 'noun' | 'adj' | 'adv' | 'phrase' | 'other';
interface Word { /* … */ pos?: Pos }
```

- У базовых слов `pos` обязателен и равен `verb`. 200 записей получают `"pos": "verb"`.
- У пользовательских слов `pos` необязателен; без него слово считается `other` в фильтре.
- Валидатор: если `pos` задан, он должен быть из списка; у `base` он обязан быть `verb`.
- Подписи на русском: глагол, существительное, прилагательное, наречие, фраза, другое.
  - `adv` включает наречия, предлоги, союзы, местоимения и вопросительные слова.
  - `phrase` — любое многословное выражение, кроме существительного с артиклем и глагола с `θα`/`να`.

### Соглашения по записи

- **Существительное:** `el` с артиклем в именительном падеже (`το κλειδί`, `η πετσέτα`).
  Во множественном только pluralia tantum (`τα λεφτά`).
- **Прилагательное:** мужской род (`ψηλός`).
- **Глагол:** 1-е лицо ед. ч. настоящего времени (`τελειώνω`, а не `τελειώνει`).
  `forms` и `conj` заполняются, если известны. Если известна только одна форма, `forms` заполняется частично.
- **Фраза:** как написано, с исправленными опечатками.
- **`ru`:** перевод; несколько значений через запятую. Пометки в скобках сохраняются
  (`встреча (официальная)`).
- **`id`:** транслитерация `el` без ведущего артикля (`o`/`i`/`to`/`oi`/`ta`); остальное как сейчас
  (`makeId`, суффиксы при коллизии).
- **Слова из Telegram:** `source: "user"`, `addedBy: "Telegram"`, `addedAt` — дата сообщения.
  Теги: тематические, свободные, на русском, 0–2 штуки.

### Ключ дедупликации

`dedupKey(el)`: нижний регистр, без диакритики, без ведущего артикля, схлопнутые пробелы.
Слово не добавляется, если такой ключ уже есть в словаре: среди базовых или пользовательских слов,
в любом регистре и с любым артиклем.

## Изменения приложения

- **Словарь:** фильтр-чипы «Часть речи» (группа ИЛИ, с другими группами — И). `WordFilter` получает
  поле `pos: Pos[]`. Слово без `pos` проходит только чип «другое».
- **Карточка слова и форма добавления/редактирования:** выбор части речи (select, по умолчанию «другое»).
  `conj` и `forms` показываются только для `pos = verb` или при пустом `pos`.
- **Карточка обучения:** часть речи выводится мелким текстом рядом со спряжением.
- **Проверка ввода (RU→EL):**
  - если `el` начинается с артикля, а ответ совпадает с `el` без артикля, результат — новый
    вердикт `article`;
  - для оценки `article` эквивалентен `accent`: оценка «Трудно», сообщение «Не забудьте артикль: …».

## Разовый импорт накопленного

Делается один раз в рабочей сессии с Claude Code. В продукт не входит, кроме итогового коммита.

1. **Извлечение.** `scripts/extract-telegram-export.ts <result.json>` выдаёт `import/candidates.json`:
   - все текстовые сообщения с датой и полным текстом;
   - исключаются сообщения без греческих букв и без кириллицы;
   - каталог `import/` в `.gitignore`.
2. **Чистка.** Её выполняют субагенты партиями по ~60 сообщений по единой инструкции (та же, что
   системный промпт бота, см. ниже). Результат — массив записей в формате бота.
3. **Сборка.** `scripts/merge-import.ts`:
   - дедуплицирует по `dedupKey` против словаря и внутри пачки; при дубле в пачке побеждает более ранняя дата;
   - присваивает `id`, прогоняет `validateWords`;
   - пишет `import/review.md`: таблица el / ru / pos / теги / заметка об исправлении;
   - пишет готовый `data/words.json` в рабочую копию.
4. **Проверка пользователем.** Таблица публикуется для просмотра. После согласия — один коммит
   `words: import N words from Telegram`.

## Бот: автоматическое пополнение

### Настройка (однократно, вручную)

- Создать бота в @BotFather и выключить privacy mode: `/setprivacy` → Disable.
- Добавить бота в группу.
- Добавить секреты репозитория: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `OPENROUTER_API_KEY`.
  - `TELEGRAM_CHAT_ID` — числовой id группы. Его печатает скрипт при первом запуске, если секрет пуст.
- Добавить переменную репозитория `OPENROUTER_MODEL` (необязательно).
- Инструкция кладётся в README.

### Workflow `.github/workflows/telegram-import.yml`

- Триггеры: `schedule: cron '17 * * * *'` (раз в час) и `workflow_dispatch`.
- `concurrency: telegram-import`, `cancel-in-progress: false`.
- `permissions: contents: write`.
- Шаги: checkout → setup-node 24 → `npm ci` → `npx tsx scripts/telegram-import.ts`.
- Скрипт сам коммитит и пушит. Деплой при этом не запускается: в `deploy.yml` `paths-ignore` расширяется с `data/words.json` до `data/**`.

### Скрипт `scripts/telegram-import.ts`

Тонкая обёртка над чистыми модулями в `src/lib/telegram/`.

1. **Чтение состояния.** Читает `data/telegram-state.json` = `{ "offset": number }`; файла нет → `0`.
2. **Получение сообщений.** `getUpdates?offset=<offset>&timeout=0&allowed_updates=["message","edited_message"]`.
   - Берутся сообщения с `chat.id === TELEGRAM_CHAT_ID`; текст — `text` или `caption`.
   - Сообщения от ботов пропускаются.
   - Если `TELEGRAM_CHAT_ID` пуст, печатаются найденные чаты (id, title), и скрипт завершается без изменений.
3. **Разбор.** Сообщения без греческих букв отбрасываются без вызова ИИ. Остальные одним запросом
   (до 30 сообщений; больше — несколькими) уходят в OpenRouter.
4. **Новые слова.** Дедупликация по `dedupKey` против текущего словаря и внутри пачки, `makeId`,
   `validateWord`. Невалидные записи пропускаются с логом. `addedAt` — дата сообщения.
5. **Коммит.** Если есть новые слова: дописать в `data/words.json` (формат как у приложения,
   `JSON.stringify(_, null, 2)` + `\n`) и обновить `offset = max(update_id) + 1`. Один коммит
   `words: add N from Telegram` с обоими файлами, затем push.
   - При отказе push (кто-то закоммитил из приложения): `git pull --rebase` и повтор, до 3 раз.
   - Если новых слов нет, но offset сдвинулся, коммитится только состояние, с сообщением
     `telegram: advance offset`.
6. **Ответ в группу.** После успешного push бот отправляет `sendMessage`:
   - «📚 Добавлено N: γράφω — писать, …» (до 10 слов, затем «и ещё K»);
   - если всё оказалось дублями: «Уже в словаре: …»;
   - если в сообщениях не было слов, бот молчит.
   - Ошибка отправки ответа не влияет на результат.

### OpenRouter

- `POST https://openrouter.ai/api/v1/chat/completions`.
- Модель: `OPENROUTER_MODEL`, по умолчанию `anthropic/claude-haiku-5.5` (проверено 2026-10-14 в каталоге OpenRouter, поддерживает structured outputs).

- `response_format: { type: "json_schema", json_schema: { strict: true, schema } }`, `temperature: 0`.
- Схема ответа: `{ words: Array<{ el, ru, pos, tags: string[], forms?: {aorist?, future?}, conj?, note?, sourceMessageId: number }> }`. Необязательные поля в strict-схеме передаются как `null`. `note` — что исправлено (опечатка, форма), только для таблицы разового импорта, в `Word` не сохраняется.
- Системный промпт, общий с разовым импортом: файл `src/lib/telegram/prompt.ts`. Содержит:
  - соглашения по записи из раздела выше;
  - что игнорировать: домашние задания («Д\З»), бытовую переписку, ссылки, вопросы преподавателю,
    объяснения правил без новых слов, предложения-упражнения;
  - исправление опечаток и приведение к словарной форме;
  - 3–4 примера «вход → выход» из реального чата.
- Ответ проверяется (структура, `pos` из списка, `sourceMessageId` из переданных). Неверный JSON →
  ошибка запуска.

### Ошибки и устойчивость

| Ситуация | Поведение |
|---|---|
| OpenRouter/Telegram недоступен, 5xx, неверный JSON | скрипт падает с ненулевым кодом, offset не сдвигается, через час повтор |
| Запись не прошла валидацию | пропускается, лог в выводе Actions, остальные добавляются |
| Конфликт push | rebase и повтор до 3 раз, затем падение (offset не сдвинут — повтор) |
| Пропуск запусков > 24 ч | Telegram удаляет старые updates — слова теряются; это допустимо, при необходимости разовый импорт повторяется |
| Отредактированное сообщение | обрабатывается как новое; дубли отсекаются по `dedupKey` |

Повторная обработка тех же сообщений безопасна: дедупликация делает её идемпотентной.

## Тестирование

Vitest:

- **`validate`:** правила `pos`.
- **`filters`:** группа `pos`, слово без `pos` → «другое».
- **`answer`:** вердикт `article`.
- **`wordId`:**
  - `stripArticle`, `dedupKey`: регистр, ударения, артикли, пробелы;
  - `makeId` для `το κλειδί` → `kleidi`.
- **`telegram/updates`:**
  - фильтр по чату, пропуск ботов, `caption`, `edited_message`;
  - расчёт следующего offset.
- **`telegram/llm`:** валидный ответ; невалидный JSON; неизвестный `pos`; чужой `sourceMessageId`.
  `fetch` — мок.
- **`telegram/merge`:**
  - дубли против словаря и внутри пачки;
  - коллизия id;
  - невалидная запись пропускается;
  - дата берётся из сообщения.
- **`telegram/reply`:** форматирование, усечение до 10.
- **`data/words.json`:** валиден, ровно 200 базовых глаголов, все с `pos: verb`.

Workflow проверяется вручную через `workflow_dispatch` после настройки секретов.
