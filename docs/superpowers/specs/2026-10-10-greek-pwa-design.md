# Greek Verbs PWA — дизайн

Дата: 2026-10-10

## Цель

PWA для двух пользователей (автор и его жена) для изучения современного греческого.
Стартовый словарь — 200 самых употребимых глаголов уровня A2, с возможностью
пополнять общий словарь из приложения. Изучение в обоих направлениях
(EL→RU и RU→EL), фильтры по словарю. Хостинг — GitHub Pages (публичный репозиторий).

Вне рамок первой версии: грамматические правила, синхронизация прогресса между
устройствами, аудиофайлы (только браузерный TTS), слова не-глаголы в стартовом наборе
(пользователь может добавить любые слова вручную).

## Критерии успеха

- Приложение устанавливается на телефон как PWA и работает офлайн (обучение, словарь).
- Слово, добавленное одним пользователем, видно второму после обновления словаря
  (без ожидания передеплоя).
- Прогресс по каждому направлению ведётся отдельно и переживает перезапуск приложения.
- Фильтры по спряжению, тегам, источнику, автору, статусу и текстовый поиск работают
  совместно и позволяют запустить сессию обучения по отфильтрованному набору.

## Стек

- Vite + Svelte + TypeScript.
- vite-plugin-pwa (манифест, service worker, автообновление).
- `idb` для IndexedDB.
- Vitest для тестов логики.
- GitHub Actions: сборка и деплой на GitHub Pages при push в `main`.

## Модель данных

### Общий словарь — `data/words.json`

Массив записей:

```json
{
  "id": "grafo",
  "el": "γράφω",
  "ru": "писать",
  "forms": { "aorist": "έγραψα", "future": "θα γράψω" },
  "conj": "A",
  "tags": ["общение", "учёба"],
  "example": { "el": "Γράφω ένα γράμμα.", "ru": "Я пишу письмо." },
  "source": "base",
  "addedBy": null,
  "addedAt": "2026-10-10"
}
```

- `id` — латинская транслитерация `el`; при коллизии добавляется суффикс `-2`, `-3`…
- `el` — словарная форма (1 л. ед. ч. настоящего времени) с ударением.
- `ru` — перевод; несколько значений через запятую.
- `forms` — `aorist` и `future`; для пользовательских слов поля необязательны.
- `conj` — одно из `A | B1 | B2 | -ομαι | irregular`; для пользовательских слов
  необязательно (может отсутствовать, если слово не глагол).
- `tags` — тематические теги на русском (массив строк, может быть пустым).
- `example` — необязателен для пользовательских слов.
- `source` — `base` (стартовый набор) или `user`.
- `addedBy` — имя из настроек устройства; `null` для `base`.
- `addedAt` — дата ISO (YYYY-MM-DD).

### Личный прогресс — IndexedDB

Ключ: `${wordId}:${direction}`, где `direction` ∈ `el-ru | ru-el`.

```ts
interface CardState {
  wordId: string;
  direction: 'el-ru' | 'ru-el';
  interval: number;      // дни; 0 — ни разу не показано
  ease: number;          // стартовое 2.5, минимум 1.3
  due: string;           // ISO-дата следующего показа
  reps: number;          // успешных повторений подряд
  lapses: number;        // общее число ошибок («Снова»)
  recent: Grade[];       // последние 5 оценок
}
type Grade = 'again' | 'hard' | 'good' | 'easy';
```

### Статусы (вычисляются, для фильтров)

- **новое** — нет записи прогресса для этого направления.
- **учу** — интервал < 21 дня.
- **выучено** — интервал ≥ 21 дня.
- **трудное** — ≥ 3 оценок `again` среди последних 5 (`recent`). Флаг «трудное»
  независим и может сочетаться с «учу»/«выучено».

### Настройки устройства — localStorage

`name`, `githubToken`, `newPerDay` (по умолчанию 10), счётчик новых слов,
показанных сегодня (по направлению).

## SRS — упрощённый SM-2

`schedule(state, grade, today) → state`, чистая функция:

- `again`: `reps = 0`, `interval = 1`, `ease -= 0.2`, `lapses += 1`.
- `hard`: `interval = max(1, round(interval * 1.2))`, `ease -= 0.15`.
- `good`: `reps == 0 → 1`, `reps == 1 → 3`, иначе `round(interval * ease)`; `reps += 1`.
- `easy`: как `good`, затем `* 1.3`, `ease += 0.15`; `reps += 1`.
- `ease` ограничен снизу 1.3. `due = today + interval`. `recent` хранит последние 5 оценок.

Режим ввода оценивает автоматически: верно → `good`, ошибка только в ударении → `hard`,
иначе → `again`.

## Проверка ввода (RU→EL)

Нормализация перед сравнением: trim, схлопывание пробелов, нижний регистр,
финальная `σ` → `ς` в конце слова. Сравнение:

1. Совпадение с `el` с учётом ударений → верно.
2. Совпадение после удаления диакритики (NFD + удаление combining marks) → ошибка
   ударения.
3. Иначе → неверно.

## Сессия обучения

- Направление выбирается переключателем; режимы: «Карточки» (оба направления),
  «Ввод» (только RU→EL).
- Очередь: все карточки с `due ≤ today` из текущего набора (весь словарь или фильтр),
  затем новые слова до остатка дневного лимита `newPerDay` для этого направления.
- Порядок: повторения перемешаны, новые — в порядке словаря.
- Карточка, оценённая `again`, возвращается в конец текущей сессии один раз.
- Итоговый экран: сколько пройдено, сколько ошибок.

## Экраны

Нижняя навигация: **Учить / Словарь / Добавить / Настройки**.

### Учить
- Переключатель направления, счётчики «к повторению сегодня» и «новых доступно».
- Кнопки «Карточки» и «Ввод» (второй — только RU→EL).
- Если запуск из словаря с фильтром — показывается активный фильтр с возможностью сбросить.
- **Карточка**: лицевая сторона — слово; по тапу — перевод, формы, спряжение, пример,
  кнопка 🔊 (Web Speech API, `el-GR`; кнопка скрыта, если голос недоступен). Кнопки
  оценки: Снова / Трудно / Хорошо / Легко.
- **Ввод**: русское слово, поле ввода, кнопка «ά» — ставит тонос над последней гласной
  перед курсором. Результат: ✅ / ⚠️ ударение / ❌ + правильный ответ и формы.

### Словарь
- Поиск по `el` и `ru`, без учёта диакритики и регистра.
- Фильтры-чипы (комбинируются через И, внутри одной группы — ИЛИ): спряжение, теги,
  источник (base/user), автор (`addedBy`), статус (для выбранного направления).
- Тап по слову — детальная карточка: все поля, прогресс по обоим направлениям,
  редактирование и удаление для `source: user`.
- Кнопка «Учить эти слова» — сессия по текущему фильтру.

### Добавить
- Поля: греческое (обяз.), перевод (обяз.), aorist, future, спряжение, теги
  (выбор существующих + новый), пример (el/ru).
- Подсказка о дубликате при вводе (сравнение без диакритики с `el`).
- Без токена или имени — кнопка неактивна, ссылка на настройки.
- Офлайн — запись в очередь (localStorage), отправка при восстановлении сети.

### Настройки
- Имя, GitHub-токен (с инструкцией: fine-grained PAT, только этот репозиторий,
  Contents: Read and write), `newPerDay`.
- Экспорт/импорт прогресса (JSON-файл).
- Кнопка «Обновить словарь».

## Работа со словарём (`dictionaryRepo`)

- **Чтение**: GitHub Contents API (`GET /repos/{owner}/{repo}/contents/data/words.json`),
  с токеном если есть (лимиты выше), иначе без. Ответ кэшируется (IndexedDB) вместе с `sha`.
  Фоллбэк при ошибке/офлайне — кэш, затем копия словаря, вшитая в сборку.
- **Запись** (добавление, редактирование, удаление): прочитать свежий файл + `sha`,
  применить изменение, `PUT` с `sha` и сообщением коммита
  `words: add γράφω (by Саша)`. На 409/422 (sha mismatch) — повторить чтение и запись,
  до 3 попыток.
- **Ошибки**: 401/403 — тост «проверьте токен»; сеть — в офлайн-очередь;
  исчерпаны повторы — тост с предложением повторить. Приложение не падает.
- Контент кодируется/декодируется в base64 с поддержкой UTF-8.

## PWA и деплой

- Манифест: название, иконки 192/512 + maskable, `display: standalone`,
  `base` = `/<repo>/`.
- Service worker (vite-plugin-pwa, `autoUpdate`): precache оболочки приложения
  и вшитой копии словаря; при обновлении — тост «обновлено».
- `.github/workflows/deploy.yml`: на push в `main` — `npm ci`, `npm test`,
  `npm run build`, публикация через `actions/deploy-pages`.
- Коммиты слов из приложения запускают передеплой — это нормально.

## Стартовый словарь

200 глаголов A2, составляются автором реализации (Claude): `el` с ударением, `ru`,
`aorist`, `future`, `conj`, 1–3 тематических тега, пример A2 с переводом.
Скрипт `validate-words` проверяет: соответствие схеме, уникальность `id` и `el`,
наличие ударения в многосложных `el`, допустимые значения `conj`.
Данные сгенерированы — рекомендуется выборочная проверка носителем, особенно
неправильных глаголов.

## Тестирование

Vitest-тесты для `src/lib`:
- `srs` — интервалы и ease для каждой оценки, нижняя граница ease, `recent`.
- `answer` — ударения, регистр, пробелы, финальная сигма, частичные ошибки.
- `filters` — каждая группа фильтров, комбинации, поиск без диакритики.
- `status` — пороги статусов и флаг «трудное».
- `session` — due + лимит новых, повтор `again` в конце сессии.
- `dictionaryRepo` — чтение/фоллбэк, запись, retry на 409, UTF-8 base64 (mock fetch).
- `validate-words` запускается в CI.

UI проверяется вручную в браузере (desktop + мобильный вид).
